# 开源协议分析：ESurfingClient-CVersion

> 分析对象：`BadGhost520/ESurfingClient-CVersion`（上游主仓库）及其在本机的一份改造副本
> **当前状态：GPL 问题已解决** —— 见文末「六、已处理」。本机这份副本现在只含
> Apache-2.0 + MIT + 公有领域代码，三种发行场景都不再有法律顾虑。

> 最初结论：**主项目是 Apache-2.0，允许你修改和发行 —— 但它静态链接的 mongoose 是
> GPL-2.0，这一条会改变你发行时的义务。** 下文保留完整分析过程。

## 三、⚠️ 坑在这里：mongoose 是 GPL-2.0

`third_party/mongoose/mongoose.h` 的头部原文：

```
// Copyright (c) 2004-2013 Sergey Lyubka
// Copyright (c) 2013-2025 Cesanta Software Limited
// All rights reserved
//
// This software is dual-licensed: you can redistribute it and/or modify
// it under the terms of the GNU General Public License version 2 as
// published by the Free Software Foundation. ...
//
// Alternatively, you can license this software under a commercial
// license, as set out in https://www.mongoose.ws/licensing/
//
// SPDX-License-Identifier: GPL-2.0-only or commercial
```

**它是 GPL-2.0-only（或商业授权二选一）。** 而 `CMakeLists.txt` 里：

```cmake
if (NOT __OPENWRT__)
    target_sources(ESurfingClient PRIVATE
            third_party/mongoose/mongoose.c     # ← 只有非 OpenWrt 构建才编进去
            src/webserver/...)
```

也就是说：

- **OpenWrt 构建**：不含 mongoose → 不受 GPL 影响 ✅
- **Windows / Linux / macOS 构建**：**静态链接了 mongoose** → 受 GPL-2.0 约束 ⚠️

### 为什么这不是「Apache-2.0 就没事」

GPL-2.0 是**传染性**许可：发行「包含 GPL 代码的可执行文件」时，你必须

1. 以 **GPL-2.0** 公开**完整的对应源码**；
2. 授予接收者 GPL 的全部自由（可再发行、可修改）；
3. 不得附加额外限制。

**而且 Apache-2.0 与 GPL-2.0-only 本身不兼容** —— Apache-2.0 的专利终止条款属于
GPL-2.0 §6 禁止的「额外限制」。Apache-2.0 与 **GPL-3.0** 兼容，与 **GPL-2.0 不兼容**
（这是 FSF 的既有立场）。

> 所以上游仓库标注的「Apache-2.0」对**桌面版构建**而言是**不完整的**。
> 这是上游既有的问题，不是你引入的 —— 但你要发行就得面对它。

### 其余依赖都是宽松许可，不构成问题

| 库 | 许可证 | 义务 |
|---|---|---|
| cJSON | MIT | 保留版权与许可声明即可 |
| LZMA SDK (`third_party/7z`) | **公有领域**（源码头部：`Igor Pavlov : Public domain`） | 无 |
| `src/utils/sim/`（simssl） | 项目自己写的（头文件保护宏 `ESURFINGCLIENT_SIMEVPINTERNAL_H`），**不是** OpenSSL | 随主项目 |

## 四、你发行时的三个选择

### 选择 A：按 GPL-2.0 发行整个桌面版
最省事的做法。公开完整源码 + GPL-2.0 许可证 + 保留归属。
代价：别人也能自由拿走你的修改（包括商业使用）。

### 选择 B：买 mongoose 商业授权
去 <https://www.mongoose.ws/licensing/> 购买，之后整个项目可以保持 Apache-2.0。

### 选择 C：去掉 mongoose（**推荐**）

新版网页界面只需要：

- 静态文件服务（`index.html` + `app.css` + `app.js` + `app.svg`）
- 6 个 REST 端点（`status/auth`、`status/online`、`status/sys`、`getConfigs`、`saveConfigs`、`applyConfigs`、`logs`）
- **不需要** TLS、WebSocket、HTTP/2、反向代理

一个最小的阻塞式 HTTP/1.1 服务器约 **300–400 行 C**，用现有 socket 代码就能写。
换掉之后：

- **所有构建**（含桌面版）都只剩 Apache-2.0 + MIT + 公有领域 → **彻底干净**
- 还能顺带解决第 3 节提到的 `logout-delay` / 外部访问无鉴权之类的安全问题

## 五、你实际要做的清单

无论选哪条路：

- [ ] 保留 `LICENSE` 副本（Apache-2.0 全文）
- [ ] **明确标注你修改了哪些文件**（§4(b)）—— 建议在 README 里写一节「改动说明」
- [ ] 保留原作者的版权与归属声明
- [ ] 不要用原项目的名字 / Logo 作为你自己的品牌（§6 不授予商标权）
- [ ] 若发行**桌面版**：在 A / B / C 里选一条

### 一句额外的情面话

上游 README 里写着：

> 不要让我发现有人拿去做路由器贩卖喔

这是作者的**请求，不是许可证条款** —— Apache-2.0 明确允许商业使用。
法律上你可以商用；但如果只是自用或开源分享，不违背作者的意愿。
