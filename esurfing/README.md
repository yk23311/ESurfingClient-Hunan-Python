# 天翼校园拨号器（Python 版，湖南）

一个用于天翼校园网（中国电信）的 Python 认证客户端，**湖南**协议适配。

## 它是什么

单文件（`run.py`，约 1500 行），只依赖 `pycryptodome`。做四件事：

1. **判定网络状态** —— 是"能上网"还是"被门户拦住了要认证"；
2. **取身份** —— 从真实网卡读 IP / MAC / 网关（不靠用户填）；
3. **认证** —— 按湖南报文格式加密、取票据、登录；
4. **保活与注销** —— 定期心跳，掉线重新认证；`logout` 正常注销。

## 用法

```bash
pip install pycryptodome

python run.py             # 认证并保持在线（Ctrl+C 只停保活，不断网）
python run.py logout      # 注销
python run.py init        # 重新填账号密码
python run.py selftest    # 离线自检，不联网
```

双击 `启动拨号.bat` 等同于 `python run.py`。

首次运行会问账号密码，写进 `config.json`（**明文**，注意保管）。

> ⚠️ 注销前先 Ctrl+C 停掉保活。保活每 60 秒探一次网，发现掉线会**自动重新认证** ——
> 不停掉的话，注销完最多 1 分钟又自己上线了。

## 协议要点（这部分是实测硬结论）

```
明文 P = XML 的 UTF-8 字节 + 0x00 + 补 0x00 到 16 的倍数     ← 不是 PKCS#7
内层 I = IV || AES-128-CBC-Encrypt(K1, IV, P)
外层 B = IV || AES-128-CBC-Encrypt(K2, IV, I)
HTTP body = B.hex().upper()                                  ← 长度是 2 × len(B)
```

两个坑，都在这里踩过：

1. **`K1` 和 `K2` 是两把独立的 AES-128 密钥，串联两层 CBC。**
   拼成一把 AES-256 会完全解不开。
2. **填充是「NUL 结束符 + 补零」，不是 PKCS#7。**
   而且那个 `+1` **只作用于明文层**，中间层本来就是 16 的倍数、不能再补。
   湖南的规则是 `ceil((L+1)/16)*16`，广东是 `ceil(L/16)*16` —— 这是两地最容易搞错的差别。

**判成功只看 `Error-Code == 0`**，且**响应体可能是 0 字节**（注销成功就是）。
要求"响应体非空且能解出 XML"会把成功的注销判成失败 —— 真实踩过。

**票据是会话级的**：`auth` / `keep` / `state` / `term` 共用同一张票，由 `ticket.cgi` 下发。
它必须落盘（`session.json`），否则注销时手里是空票，服务端回 `Error-Code=1`，**注销静默失败**。

## 离线自检

`python run.py selftest` 不联网，检查四项：

1. 加解密往返是否一致；
2. 长度公式与 5 个官方样本的 body 长度是否吻合（265→608、299→672、246→576、361→800、384→864）；
3. **内嵌的一份真实抓包**能否解开并**回加密到逐字节一致** —— 这一项才真正证明密钥是对的，
   而不只是"自己跟自己自洽"；
4. `Error-Code` 判据，含小写头（中间设备可能规范化大小写）。

## 环境与网络判据

**先看网关能不能通，再看第一跳，网段只作参考。**

三个反直觉的点，都是踩出来的：

- **校园网关只回 ICMP/ARP，不监听 TCP。** 用 TCP 探测会得到假阴性，整个"在不在校园网"的
  判断会因此反转。本程序用 ICMP（`ping`），失败才退回 TCP。
- **网卡上有 IP ≠ 在校园网。** 拔线后 Windows 会保留上次的 DHCP 租约（僵尸租约）。
- **不能只看 IP 网段。** 本校同时有 `100.67.x.x`（CGNAT）和 `10.82.66.x`（RFC1918）两个网段，
  而手机热点也用 `10.x` —— 光看网段分不出来。

## 已知不足

按重要性排：

1. **只有湖南能用。** `Algo-ID`、密钥、门户地址都是湖南的，其它省份不通用
   （广东的流程是"运行时发现"，这里没有实现）。
2. **`local-time` 字段的生成规则没破解。** 官方抓包里出现过 `00000000j/k/l/m/013/014/017`，
   本程序用固定占位值，服务端一直接受 —— 但**没做控制实验**，不知道边界在哪。
3. **ZSM 算法协商未实现**（广东需要，湖南不需要）。遇到 ZSM 类型的响应只会报错。
4. **字段顺序是否影响服务端解析没验证过。** 本程序与官方抓包一致，但没做重排实验。
5. **`excheck-args` 里 `hello` / `conn` 的语义不明。**
6. **错误恢复粗糙。** 认证失败后的重试是简单固定间隔，没有退避策略；
   长时间断网后的行为没有系统测过。
7. **没测过并发或多账号。** 单账号单实例，没考虑同时跑多个。
8. **`config.json` 是明文账号密码**，没有加密也没有权限保护。
9. **Windows 专用** —— 网卡枚举走 `GetAdaptersAddresses`，其它平台没适配。

## 已验证 / 未验证

**实测通过**（有原始日志，未随仓库发布）：

- 与 32 份真实抓包在解密 + 回加密上**逐字节一致**
- 五个端点的请求体与官方样本**同长**（auth 672 / keep 864 / state 576 / term 608）
- 校园网内真实认证成功：`auth=0 state=0 keep=0`
- 注销成功：`term.cgi` 返回 `Error-Code=0`，出网随即断开

**没验证**：就是上面「已知不足」里那几条。

## 安全

- `config.json` 是**明文账号密码**。
- `session.json` 是**有效会话票据**，注销要用。
- 两者都在 `.gitignore` 里，不要外传、不要提交。
